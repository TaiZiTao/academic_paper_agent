# 单篇论文精读功能设计规格

## 1. 目标

在现有 GraphRAG 企业知识问答平台中增加独立的“论文助手”模块，首期完成单篇科研论文的深度阅读闭环：

- 上传中文或英文的文本型 PDF。
- 自动解析论文结构并建立页码可追溯索引。
- 自动生成中文精读报告，同时保留关键英文术语。
- 支持围绕当前论文连续问答。
- 按需生成章节翻译、学习笔记和汇报提纲。
- 所有重要结论均能关联原论文和真实页码，并可跳转到对应 PDF 页面。

该模块复用 GraphRAG 的 FastAPI、Vue 3、SQLite、SSE、LLM、Embedding 和检索基础设施，但使用独立的论文数据模型与工作流，避免把论文精读逻辑硬塞进现有通用知识库问答流程。

## 2. 首期范围

### 2.1 包含

- 单篇论文上传、解析、索引、阅读和删除。
- 中文、英文文本型 PDF。
- 自动精读报告。
- 单篇论文连续问答。
- 章节翻译。
- 学习笔记。
- 汇报提纲。
- 来源论文、页码、章节和原文片段级引用。
- PDF 页码跳转。
- 任务状态、产物和会话持久化。

### 2.2 暂不包含

- 扫描版 PDF OCR。
- 引用句在 PDF 中的精确高亮定位。
- 多篇论文横向比较和综述生成。
- 自动联网检索和下载论文。
- Word、LaTeX 等非 PDF 输入。

多篇论文比较作为第二阶段扩展，首期数据模型必须预留 `paper_id` 边界，避免后续重构。

## 3. 总体方案

采用“共享基础设施、独立业务模块”的方案：

- 保留现有知识库问答模块及其 8 节点工作流。
- 新增 `app/paper/` 后端模块，承载论文解析、索引、精读工作流、任务和引用校验。
- 前端新增“论文助手”入口和独立工作台。
- 复用现有 LLM、Embedding、SQLite、SSE、日志和配置体系。
- 复用 FAISS 与 BM25 的混合检索能力，但所有检索必须限定当前 `paper_id`。
- Paper-Agent 仅作为交互和功能拆分参考，不直接合并其代码和架构。

## 4. 用户界面与交互

### 4.1 入口和列表

主导航新增“论文助手”。论文列表展示：

- 标题、作者、上传时间。
- 当前处理状态。
- 语言和页数。
- 最近一次打开时间。
- 打开、重试和删除操作。

### 4.2 上传流程

用户上传 PDF 后自动执行：

1. 提取页面文本。
2. 识别元数据和章节。
3. 生成页码感知分块。
4. 建立向量与关键词索引。
5. 生成精读报告。
6. 校验引用并保存产物。

前端通过 SSE 实时展示“解析、章节识别、索引、报告生成、引用校验、完成”等状态。只有全部必要步骤成功后，论文状态才能变为 `ready`。

### 4.3 阅读工作台

采用三栏布局：

- 左栏：论文元信息、章节目录和任务入口。
- 中栏：精读报告、问答、翻译、笔记、汇报提纲。
- 右栏：内嵌 PDF 阅读器。

点击引用后，右侧 PDF 阅读器跳转至相应页面。首期不要求引用句高亮。

## 5. 后端模块边界

新增目录建议如下：

```text
app/paper/
├── models.py       # 论文领域数据结构
├── schemas.py      # API 请求与响应模型
├── parser.py       # PDF 页面文本、结构与元数据解析
├── chunker.py      # 页码感知分块
├── indexer.py      # 当前论文的 FAISS + BM25 索引
├── retriever.py    # 按 paper_id/section 检索
├── graph.py        # PaperReadingGraph
├── nodes.py        # 工作流节点
├── prompts.py      # 报告、问答、翻译等提示词
├── citations.py    # 引用生成与校验
├── service.py      # 用例编排和事务边界
└── router.py       # FastAPI 接口与 SSE
```

具体文件可在实现阶段按现有项目规范调整，但论文模块必须与通用知识库工作流保持清晰边界。

## 6. PDF 解析和页码真值

### 6.1 页面文本

以 `pdfplumber` 逐页提取结果作为页码真值，每段文本从产生时即携带页码，避免后处理猜测页码。

MinerU 作为可选的结构增强器，用于识别标题、章节、公式和表格结构；MinerU 失败时回退到 `pdfplumber`，不应使文本型 PDF 整体失败。

### 6.2 章节识别

章节识别结合：

- PDF/Markdown 标题结构。
- 常见章节名规则，如 Abstract、Introduction、Method、Experiments、Conclusion。
- LLM 对模糊标题进行归类。

章节边界必须最终映射回页面范围。

### 6.3 分块元数据

每个论文分块至少包含：

- `paper_id`
- `chunk_id`
- `section`
- `page_start`
- `page_end`
- `content`
- 文档内顺序或字符位置

跨页分块必须记录起止页；引用时优先选择支持证据首次出现的页面。

## 7. PaperReadingGraph

自动精读报告采用独立的 LangGraph 工作流：

1. `MetadataExtract`：提取标题、作者、摘要、关键词等元信息。
2. `SectionAnalyze`：识别章节和每章功能。
3. `ContributionExtract`：提取研究问题、方法、实验、结果、创新和局限。
4. `ReportSynthesize`：生成结构化中文精读报告并保留英文术语。
5. `CitationVerify`：逐条核验引用来源、页码和原文证据。
6. `ArtifactPersist`：保存报告、引用、状态和任务记录。

精读报告默认包含：

- 论文元信息。
- 研究背景与问题。
- 方法与技术路线。
- 实验、数据集和指标。
- 主要结果。
- 创新点。
- 局限性。
- 可继续研究的问题。
- 中英双语关键术语。

## 8. 按需任务

问答、章节翻译、学习笔记和汇报提纲共用一套任务管线：

1. 确定任务类型和当前论文。
2. 根据任务需要限定章节。
3. 在当前 `paper_id` 下执行混合检索。
4. 生成任务结果。
5. 校验引用。
6. 通过 SSE 返回并持久化产物。

问答需保留同一论文下的短期会话上下文；翻译以章节为输入边界；笔记和汇报提纲应保存为可再次打开的产物。

## 9. 数据模型

新增以下核心实体：

### `papers`

保存文件名、标题、作者、摘要、语言、页数、文件路径、处理状态、错误码及时间字段。

### `paper_sections`

保存章节名称、层级、顺序、起止页和摘要。

### `paper_chunks`

保存页码感知分块、章节、内容、顺序及索引关联信息。

### `paper_tasks`

保存报告、问答、翻译、笔记和提纲任务的类型、状态、输入和错误信息。

### `paper_artifacts`

保存任务生成的结构化内容、展示文本、引用集合和版本信息。

## 10. 引用协议与校验

引用采用结构化对象，不从最终 Markdown 文本反向解析：

```json
{
  "paper_id": 12,
  "paper_title": "Example Paper",
  "page": 6,
  "section": "Experiments",
  "chunk_id": "paper-12-chunk-31",
  "quote": "Supporting text from the paper"
}
```

`CitationVerify` 必须验证：

- `chunk_id` 存在。
- 分块属于当前论文。
- 页码位于分块和论文有效范围内。
- `quote` 能在对应分块或规范化页面文本中找到。

校验失败时，允许携带错误原因重新生成一次。再次失败的结论标记为“原文未提供充分证据”，不得编造页码。若只能确认论文和原文片段而无法可靠确认页面，则引用降级为无页码形式。

## 11. 错误处理与一致性

- PDF 无可提取文本：状态为 `failed`，错误码 `unsupported_scan`，提示首期不支持扫描版。
- MinerU 失败：自动回退到 `pdfplumber`。
- Embedding 或索引失败：错误码 `index_failed`，不得继续生成报告。
- LLM 失败：保留已完成的解析和索引，任务标记失败并允许重试。
- 引用页码无效：降级引用，不输出虚假页码。
- 删除论文：清理数据库记录、原 PDF、生成产物、向量索引和 BM25 数据。
- 部分步骤失败时不得把论文标记为 `ready`。

## 12. 第二阶段扩展

在首期稳定后增加多篇论文比较：

- 创建论文集合。
- 按论文维度隔离检索证据。
- 对研究问题、方法、数据集、指标、结果和局限进行结构化横向比较。
- 生成比较矩阵与综述草稿。

首期所有分块、引用、任务和产物均通过 `paper_id` 关联，为该扩展保留数据基础。

## 13. 首期验收标准

1. 可上传一篇中文或英文文本型 PDF。
2. 系统保存逐页文本、章节和页码感知分块。
3. 上传后自动生成中文精读报告并保留英文术语。
4. 报告包含方法、实验、创新点和局限性。
5. 可围绕当前论文进行连续问答。
6. 重要结论的引用来自真实分块并具有可靠页码。
7. 点击引用可打开 PDF 对应页面。
8. 可按需生成章节翻译、学习笔记和汇报提纲。
9. 页面刷新后论文、任务、产物和引用仍可恢复。
10. 删除论文后，其数据库、文件和索引资源被完整清理。

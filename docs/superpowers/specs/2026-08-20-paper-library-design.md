# 论文库管理: 研究方向分组 + 时间倒序(设计方案)

> 日期: 2026-08-20
> 状态: 已批准(用户确认 A 方案: LLM 自动分类 + 可修改)
> 说明: 本项目当前不是 git 仓库, 本文档落盘后不执行 commit。

## 1. 目标

论文库从"平铺列表"升级为"按研究方向分组的研究档案库", 支撑 100+ 篇论文的快速浏览:

- 按研究方向(超分辨率/去雾/去噪/检测/分割等)分组展示, 每组含论文数与标题;
- 组内按上传时间倒序(新上传在前);
- 方向由 LLM 根据摘要/关键词自动推断, 不在预置列表时自动新增(方向列表动态增长);
- 任意论文可手动改方向, 可新增自定义方向(自动分类兜底 + 人工修正);
- 保留现有上传/删除/重试/打开工作台能力; 搜索增强(标题/摘要/作者)。

## 2. 范围

### 2.1 本次做

1. 论文表新增 research_field 字段(研究方向, 自由文本);
2. 解析流程增加"研究方向自动分类"(LLM 按摘要/关键词推断, 参考预置方向列表, 输出自由文本);
3. 列表 API 支持按方向筛选 + 按方向分组返回(方向清单 + 各组论文, 组内时间倒序);
4. 更新方向的 API(改方向/新增方向);
5. 前端论文库页: 方向侧栏/分组视图, 组内时间倒序, 搜索增强, 方向可改。

### 2.2 本次不做(后续阶段)

- 论文发表年份提取/按年份筛选(需要额外提取);
- 批量操作(多选删除/打标签);
- RAG 全库问答/同方向推荐(方案 B 下一步, 研究方向届时成为检索/推荐元数据);
- 前端展示"论文发表年份"。

## 3. 数据模型

### 3.1 papers 表新增字段

research_field VARCHAR(128) DEFAULT ''   -- 研究方向(自由文本, 空=待分类/其他)

### 3.2 预置方向列表(仅作 LLM 参考与前端分组默认顺序)

底层视觉: 超分辨率/图像去雾/图像去噪/图像修复/低光增强/图像复原;
通用视觉: 目标检测/图像分割/图像生成/视觉Transformer/多模态;
其他: 医学影像/遥感影像/OCR文档/NLP大模型/其他。

LLM 输出不限于此列表——遇到新方向(如图像去雨)时自由输出, 前端自动纳入方向清单。

## 4. 研究分类流程

### 4.1 触发时机

论文解析完成后(已有 abstract/keywords)即触发一次 LLM 分类, 失败不阻断主流程(方向留空, 用户在库管理页可手动补/改)。

### 4.2 Prompt 设计(新增到 app/paper/prompts.py)

输入: 论文标题 + 摘要(截断) + 关键词;
输出: 单一研究方向短语(JSON field), 参考预置列表但允许新方向; 判不出时输出"其他"。

### 4.3 失败降级

LLM 调用失败/超时 → research_field 保持空串; 前端分组时归入"未分类", 用户可手动设置。

## 5. API 设计(app/paper/router.py + service.py)

### 5.1 列表(扩展现有 GET /api/v1/papers)

新增可选参数: field(方向精确筛选), group(是否按方向分组返回)。

GET /api/v1/papers?field=图像去雾           # 单方向筛选(平铺, 时间倒序)
GET /api/v1/papers?group=true              # 分组返回
# 分组返回结构:
{
  groups: [
    {field: "图像去雾", count: 12, items: [PaperSummary...]},   # 组内 created_at 倒序
    {field: "未分类", count: 3, items: [...]}
  ],
  fields: ["图像去雾", "图像去噪", ...],   # 全量方向清单(用于侧栏/筛选)
  total: 15
}

### 5.2 更新方向

PUT /api/v1/papers/{paper_id}/field   body: {field: "图像去噪"}
# 更新 research_field; 前端随后刷新分组

## 6. 前端设计(web/src/views/PaperListView.vue)

- 顶部: 上传/搜索保留; 新增"方向筛选"下拉(方向清单, 含"全部/未分类");
- 分组视图: 每个方向一个区块(标题 + 论文数), 组内卡片按上传时间倒序; 未分类区放最后;
- 卡片: 新增"方向"标签(可点击修改, 弹窗输入新方向或选预置);
- 搜索: 扩展为标题/摘要/作者匹配(现有只搜标题/文件名);
- 排序: 默认组内按 created_at 倒序; 平铺视图(全部)也按 created_at 倒序。

## 7. 交互细节

- 方向修改: 卡片上方向标签可点击 → 弹窗(预置方向列表 + 输入框新增); 保存后调 PUT 并刷新分组;
- 未分类: research_field 为空或"其他"时归入"未分类"区(可手动分类);
- 分组为空: 某方向删空后从分组中消失; 方向清单动态来自当前库。

## 8. 验证

1. 上传一篇新论文(如超分论文) → 解析后 research_field 自动为"超分辨率";
2. 上传/构造 5+ 篇跨方向论文 → 分组正确、组内时间倒序;
3. 手动改方向 → 分组即时移动; 新增自定义方向 → 进入方向清单;
4. 搜索标题/摘要/作者 → 命中正确;
5. 后端测试(分类 prompt、分组 API、改方向 API) + 前端 build/vitest;
6. 回归: 现有 5 篇论文上传/精读/翻译不受影响。

## 9. 后续衔接(方案 B)

research_field 存入后, 下一步"全库问答 + 同方向推荐"可直接用该字段过滤; 论文聚合索引(方案 B)会把 research_field 写入 chunk metadata。
## 10. 迁移与兼容(冲突规避)

三处必须同步改的契约点, 避免与现有代码冲突:

1. **DB 迁移**: papers 表已存在, create_all 不会加新列。需在数据库初始化处加幂等迁移——检查 information_schema/PRAGMA 列是否存在 research_field, 不存在则 ALTER TABLE ADD COLUMN;
2. **序列化契约**: _paper_dict 增加 research_field 字段, 前端 PaperSummary 类型同步加 field 字段(TS 类型), 否则类型不匹配;
3. **排序变更**: list_papers 现按 updated_at.desc(), 分组视图改为组内 created_at.desc()(上传时间倒序); 平铺模式(不传 group)保持兼容, 但排序统一为 created_at.desc() 以符合"新上传在前"。

向后兼容: 列表 API 的 field/group 均为可选参数, 不传时行为与现在一致; 解析流程新增分类为独立步骤, 不动现有解析/索引/报告/图表; 前端只改 PaperListView.vue, 不碰其他页面。

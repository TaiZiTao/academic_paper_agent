# 论文智答 README 重写设计

## 目标

将 README 重写为兼顾秋招项目展示与开源部署的综合文档。读者应在首页快速理解项目价值，并能根据文档完成本地启动、功能体验和代码定位。

## 目标读者

- 招聘者与面试官：关注 Agent Workflow、RAG、引用可信性、记忆和评测结果。
- 开发者：关注依赖、配置、启动、数据目录、API、测试和故障排查。
- 普通使用者：关注三大功能、页面入口、操作流程和结果溯源。

## 信息架构

README 按以下顺序组织：

1. 项目定位、技术栈徽章和功能概览。
2. 文献搜索下载、单论文研读、多论文问答三大功能。
3. 系统架构与从论文发现到可信回答的数据流。
4. 三套 LangGraph Agent Workflow：文献检索 5 节点、单论文报告 6 节点、多论文问答 11 节点。
5. PDF 解析、章节/图表提取、分块翻译和页码映射。
6. FAISS + BM25 混合检索、论文独立索引和多论文聚合检索。
7. 引用校验、会话记忆、SQLite 持久化和 SSE 可观测。
8. 评测结果与指标口径。
9. 环境准备、配置、前后端启动和生产构建。
10. 数据存储、API、项目结构、测试、故障排查和 License。
11. 二次开发说明放在末尾，避免喧宾夺主。

## 准确性边界

- 项目是 Hybrid RAG，不称为 GraphRAG 或知识图谱系统。
- 项目包含三套场景化 LangGraph Workflow，不称为 Multi-Agent 协作系统。
- 只有文献搜索显式定义 `SearchAgent` 类；另外两套以状态、节点和编译图实现。
- 单论文 6 节点图用于报告生成；翻译、问答、PPT 和模拟审稿由 PaperService 任务能力提供。
- 论文模块的记忆是 LangGraph State、SQLite 消息持久化和最近 10 条历史注入，不称为三级记忆。
- BM25 索引在内存中由 `chunks.pkl` 重建，不声称存在独立 BM25 索引文件。
- 只使用已完成评测的真实指标，并注明样本规模与指标含义。

## 表达原则

- 首页先讲用户价值，再讲实现细节。
- 节点职责使用中文，保留 `State → Node → Conditional Edge`、Hybrid RAG、SSE 等岗位关键词。
- 使用 Mermaid 或文本图展示架构、工作流和存储关系，不逐个解释低价值节点。
- 安装命令以仓库实际依赖和脚本为准，不依赖本机绝对路径。
- 不展示 API Key、论文原文、本地数据库或个人环境路径。

## 验收标准

- 三大功能、三套 Workflow、Hybrid RAG、引用、记忆、存储和评测均有独立说明。
- README 中不存在“Multi-Agent”“三级记忆”“588 项测试”等过期或不准确表述。
- 所有环境变量、命令、API 路径和目录名称能够在仓库中找到对应实现。
- 新用户可以仅根据 README 完成后端与前端启动。
- Markdown 标题锚点、表格、代码块和相对链接可在 GitHub 正常渲染。
